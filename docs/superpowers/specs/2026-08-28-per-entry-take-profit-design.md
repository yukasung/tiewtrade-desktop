# Take Profit รายไม้ แทนระดับ Entry Pair

วันที่: 2026-08-28

ต่อจาก [2026-08-25-entry-pair-take-profit-design.md](2026-08-25-entry-pair-take-profit-design.md)

## ปัญหา

บนตาราง Position ผู้ใช้เห็นสองแถวที่จ่ายคนละราคา (80,553.87 กับ 80,489.40) แต่คอลัมน์
Take Profit อ่านค่าเดียวกัน เพราะทั้งคู่อยู่ Entry Pair เดียวกันและเป้าถูกวัดจากราคาเฉลี่ยของ
Pair ผู้ใช้ยืนยันว่าต้องการ **เป้ารายไม้** — ไม้ที่ถัวลงมาต่ำกว่าต้องออกได้ก่อนโดยไม่ต้องรอ
ไม้ที่จ่ายแพงกว่า

คำขอนี้ขัดกับ `PRODUCT.md` §5 และ `CONTEXT.md` เดิมที่ระบุว่า "Take Profit มีสองระดับ
ไม่มีเป้ารายตัวของแต่ละ Entry" และ "Entry Pair เป็นหน่วยที่ถูกขาย" จึงยืนยันกับผู้ใช้ก่อนแล้ว
จึงแก้ spec ทั้งสองไฟล์พร้อมโค้ด

## การตัดสินใจ

### 1. Entry เป็นหน่วยที่ถูกขาย แทน Entry Pair

`Basket.pair_take_profit_price(pair)` → `Basket.entry_take_profit_price(entry_number)`
วัดจาก `entry.price` คู่กับ `entry.atr` ของ Fill ไม้นั้นเอง

ผลข้างเคียงที่ดี: เป้าของไม้ **ไม่ขยับอีกเลย** หลัง Fill เพราะไม่ใช่ค่าเฉลี่ย เดิมเป้า Pair ต้อง
คำนวณใหม่เมื่อไม้ใดไม้หนึ่งของ Pair ถูกปิด ตอนนี้เหลือเพียงเป้า Basket เท่านั้นที่ยังต้อง
restate ตาม `_remeasure_targets()`

### 2. ตาข่ายระดับ Basket ยังอยู่เหมือนเดิม

ผู้ใช้ขอเปลี่ยนระดับปกติ ไม่ได้ขอถอดตาข่าย จึงคงไว้ พร้อมลำดับเดิม: เป้ารายไม้มีผลก่อน
(เรียงจากเป้าที่ตลาดไปถึงก่อน) แล้วจึงกวาดส่วนที่เหลือที่เป้า Basket — เหตุผลเรื่อง limit order
ที่ราคาต่ำกว่าต้อง Fill ก่อน ยังเป็นเหตุผลเดิมจากสเปก 25 ส.ค.

### 3. Cooldown ยังผูกกับ Entry Pair ตามเดิม

Entry Pair ยังเป็นหน่วยของ Cooldown และของการนับ `completed_pairs` — เป็นกฎเรื่อง
*จังหวะเข้า* ไม่ใช่ *จังหวะออก* จึงไม่ถูกแตะ `entry_pair.py` ไม่มีการแก้ไข

### 4. คอลัมน์ Average บนตาราง Position เปลี่ยนความหมาย

เดิมเป็นราคาเฉลี่ยของ Pair ที่แถวนั้นสังกัด ซึ่งมีไว้อธิบายว่าเป้าในแถวถูกวัดมาจากอะไร
ตอนนี้เป้าวัดจาก Entry Price ที่อยู่ข้าง ๆ อยู่แล้ว คอลัมน์นี้จึงเปลี่ยนเป็น **ราคาเฉลี่ยของ
Basket** ซึ่งเป็นตัวตั้งของตาข่าย และยังบอกได้ว่าราคาของแถวนี้อยู่ตรงไหนเทียบกับไม้อื่น

### 5. คำเตือนตอน Start อ่านจากกฎเดียวกับที่ขาย

`sweeps_on_start` → `sells_on_start` และเปลี่ยนจากถาม `reaches_take_profit` (เป้า Basket
อย่างเดียว) เป็นถาม `take_profit_exits(price, price)` เพราะตอนนี้ไม้เดียวที่เลยเป้าตัวเองก็ถูก
ขายทันทีที่ Start ได้ โดยที่ตาข่ายยังไม่ถูกแตะ ถ้าถามแค่ตาข่ายจะมีการขายที่ไม่ได้ถูกเตือน

## ผลกระทบที่ต้องบอก

- Basket ที่เปิดค้างข้ามการอัปเกรดจะได้เป้าชุดใหม่ทันทีที่ Runtime หยิบกลับมา — เป้ารายไม้
  ไม่เคยถูกเก็บลงฐานข้อมูล (คำนวณจาก `trade_fills.entry_atr` ทุกครั้ง) จึงไม่มี migration
- ไม้ที่จ่ายแพงกว่าจะรอเป้าที่สูงกว่า ไม่ได้ถูกไม้ถูกกว่าฉุดออกไปด้วยอีกแล้ว ยกเว้นตาข่ายทำงาน
- ค่าคาดหวังของ deterministic replay (`23.679`) ไม่เปลี่ยน เพราะ Basket ใน
  `tests/fixtures/btcusdt_5m_tracer.csv` มี Entry เดียว เป้าทั้งสองระดับจึงเป็นราคาเดียวกัน
